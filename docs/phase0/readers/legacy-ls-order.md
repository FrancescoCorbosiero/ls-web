## 3. Discrepancies and corrections to the brief

1. §1 "`ls-order@main:` = `origin/main` @ `e9d2072`": the checkout has no `main` ref; write "`e9d2072` (the state of `main`, 2nd commit of `dev`)". `start-server.bat` existed only between `704a020` and `1b5458f` (`git show --stat 1b5458f`).
2. §3 "the deployed bundle must carry a different `HOST` … (inferred)": stronger than inferred — a page served from `https://ordini.logisticasanchez.com` cannot `fetch` an `http://` host (mixed content is blocked by every current browser), so the live build necessarily uses an `https` host (`rest-constant.js:2`); which one remains OP-U6.
3. §5.3 regex examples: add that the phone regex also accepts `+393292396962` (no spaces) and the dotted/dashed US forms; the e-mail regex accepts `a@b..c` and non-ASCII local parts (`costant.js:26-27`, re-run). The backend's pattern is looser for phones (12a B2), so legacy rows hold only values that pass both.
4. §6.3 "`parseFloat(x.toFixed(2))`": the rounding is `Number.prototype.toFixed` on the binary double, not decimal HALF_UP: `10×10×50 cm, q=1` → `0.01`, but three `10×10×35 cm` (0.0105) → `0.01` and `1.005` → `1.00` (re-run). CUS-04 "computed as today" should say "per line, 2 decimals, HALF_UP on the decimal value", accepting that half-cent edge cases may differ from the legacy display.
5. §6.2 "Fallback: … Reachable only through OP-04": also reachable when the pallet-type menu was never opened but the service menu was, in any order — `typeSelected` is one module flag never reset, not even by "Annulla" (`component-handler.js:11, 107, 133`); worth stating in OP-04.
6. §10 OP-S5: the enumeration `id` is also interpolated unescaped, into an unquoted attribute (`dropdown-component.js:38, 60`), not only `label`.
7. §10 OP-23: add `aria-labelledby="my-dialog-title"` pointing to an id that does not exist (the titles have other ids) and `id="my-dialog-content"` duplicated by the two dialogs (`dialog-components.js:24-25, 27, 29, 90-91, 93, 95`); and one `<meta>` carrying both `charset` and `name="viewport"` (`index.html:6`, non-conforming; NOT CHECKED whether every browser honours the viewport part).
8. §2 "puts SVG arrows in the buttons": only until the first click — `setNextButtonToReadyState()` replaces the forward button's content with the Material-icon ligature and drops the `#next-step-button-icon-id` span (`ui-handler.js:55-60, 75-76`). Cosmetic; drop.
9. §9 commit `6176e85` also removed the `orderNotes: ""` initialiser from `userData` (`git show 6176e85 -- js/components/data/user-data.js`); harmless because `saveOrderData` always sets it, but §2's "all data lives in `userData`" (:3-21) lists no `orderNotes` key — the field is added at runtime (`data-handler.js:65`).

* The menu click handlers accumulate at every opening (OP-24), so after N openings a choice runs N identical handlers — idempotent, no functional effect.

## 6. Risks and unknowns

* OP-U1 (answered by 12a B1): `DECLINED` exists for rows declined before 2024-07-22 and makes the portal show "Errore"; `NEW` also covers unverified customers. CUS-01/02 must treat an unverified e-mail as known. OP-U2 (12a B2/C1): 409 on a REGISTERED duplicate, 500 on PENDING, 500 for a non-REGISTERED order — the portal showed "Errore" in every case. OP-U4 (12b §2): six services, id 0 = none. OP-U5 (12b §4.3): one `pallet` row per unit, totals computed server-side, order volume rounded to an integer. OP-U7 → Q-24 default (DDT required, "Numero Colli" stored). OP-U9 (12b §4.4): `destinatario.email` is stored in a NOT NULL column and never used for the recipient.
* OP-U6 still unknown: deployed commit and `HOST` of `ordini.logisticasanchez.com`, CORS origins. Cut-over (MIG-03) must keep the live bundle's host answering or redirect it until DNS moves.
* OP-U3 and OP-U8: outside this repo (12c / 12a).
* R-1 data quality for the importer: client rules were stricter than the backend in some places (US phone forms, `^\d+$`, 5-digit CAP or ZIP+4) and looser in others (`0` dimensions, 10-char ZIP+4 → 400 server-side); legacy rows hold the intersection. `servizioAccessorio` 1 may mean "none" for orders of 2024-05-19…25 (12b DQ-07); `type` 1 may be the OP-04 fallback; OP-01 may have stored recipient data as a customer's registration (or vice versa) in the same page session; OP-02 allows identical consecutive orders; OP-11 case-variant e-mails.
* R-2 the two "Totale" numbers the office saw in the portal were never sent; ADM/CUS order detail must recompute from lines (08 §4.6), not display the legacy integer aggregate.
* R-3 rounding semantics (§3.4) — negligible financially (volumes are informative), but fix the rule in a test.
* R-4 the hint's second sentence and the "click Avanti" sentence are tied to the old flow; the owner reviews the adapted copy at the next gate (CLAUDE.md "Decisions and the owner").

## 7. Notes for the planner

* ADR 0001 inputs: the portal is 2.1 k lines of vanilla ES modules with no build, so the new customer area needs no client framework — server-rendered pages plus the design-system widgets (CLAUDE.md conventions) cover the wizard; the only client-side logic to keep is live totals and line add/remove, which must be mirrored server-side in `BigDecimal` (the server is the source of truth). Wizard state must live server-side (draft order or signed form state), not in memory, so a reload does not lose the order and an idempotency key prevents OP-02. Same origin for pages and API removes CORS and the `HOST` problem. The four `/mono/api/customer|order|enumeration` endpoints are retired with the portal (PROMPT.md keeps only `order/trace/state`); confirm against chapter 02 before Phase 1 closes the URL map.
* Module ownership (10 §2): CUS-01 → `auth` (one-time link) + `customers` (known/unknown routing); CUS-02, CUS-03 → `customers`; CUS-04 → `orders` (wizard, lines, totals, temporary code, idempotency, recipient); the accessory-service list → `orders` as a seeded reference table (ADM-10), the legacy enumeration endpoint is not kept. Copy → message bundles (integrator); the texts of §5 are the proposed keys.
* Phase 1 needs: schema columns for `order.transport_document_code` (required), `order.package_count` (nullable, "Numero Colli"), `order.accessory_service` (default none), recipient fields with optional phone and optional e-mail, `order_line {type PALLET|EPAL, height_cm, length_cm, width_cm, weight_kg, quantity}` integers ≥ 1 with a lenient CHECK for imported rows, `customer.phone` nullable for legacy rows only; validation utilities shared by `customers` and `orders` (Italian CAP `^\d{5}$`, Italian/E.164 phone normaliser, trimmed lower-cased e-mail); a totals service with the vectors of §5; test tags `@Tag("CUS-04")`, Playwright `[CUS-04]`.
* Tests to carry over as acceptance lists: must accept `0362 123456`, `02 12345678`, `+39 0362 123456`, `3292396962`, `+39 329 239 6962`; must reject `+1 (555) 123-4567`, `20831-1234`, dimensions `0`, `12,5` for dimensions (decimals for weight only if Q-35 says so).
