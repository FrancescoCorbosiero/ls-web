# 11 · Open questions for the owner

Questions that neither the legacy code nor this brief can answer. This is the **master
list**: each row has a recommended default, the gate by which an answer is useful, and a
column for the owner's decision. **No question blocks the work:** without an answer the
default stands, and the owner can change it later. Detailed technical questions live in the chapters and
are referenced here: `OP-U*` (03, order portal), `CMS-*` (04), `LPS-*` (05, old site),
`CU-*` and the production probes `P-01…P-07` (02 §11), `DQ-*` (08 and 12b, data quality),
`PR-01…PR-14` (07 §8, pricing), `SEC-*` (12a §5) and `F-*` (12d §3).

Rows marked **Legacy:** carry what the backend source (chapter 12) says; the owner only
confirms them or decides to change the behaviour.

Rules for the building agents:
* For an unanswered question, implement the recommended default behind one clear seam (a
  setting or a single method, with a `Q-xx` comment), list it in the next gate summary and
  carry on. Never guess silently; add new questions here.
* When the owner answers, write the answer in the "Decision" column (in English, with the
  Italian original in quotes), with the date and the gate, and update the seam, the tests
  and the affected ADR in the same commit. Agents and later sessions take decisions only
  from this file and `docs/adr/`, never from the chat.
